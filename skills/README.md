# skills/ — جریان‌های کاریِ نگهداریِ BorsTerminal

این اسکیل‌ها دستورِ کارِ دستیار (agent) برای نگهداریِ همین پروژه‌اند: هر کدام یک «قبل/بعدِ تغییر» را پوشش می‌دهد. در محیط‌هایی که اسکیل‌ها از مسیر `skills/<name>/SKILL.md` خوانده می‌شوند، همین فایل‌ها منبعِ معتبرند.

| اسکیل | چه‌وقت |
| --- | --- |
| `bors-architecture` | **پیش از** هر بازآرایی، جابه‌جاییِ فایل، تغییرِ ساختار، افزودن/حذفِ وابستگی یا ویرایشِ specِ PyInstaller — بررسیِ ساختار و ارائهٔ نقشهٔ تغییر به‌جای بازنویسیِ کورکورانه |
| `bors-build-release` | هنگامِ ساختِ نصاب، بریدنِ ریلیز، امضای فایل‌های آپدیت، انتشار روی GitHub یا عیب‌یابیِ بیلد/آپدیت |
| `bors-code-review` | **بعد از** نوشتنِ کد و **پیش از** کامیت — بازبینیِ امنیت، باگ، race، لبه‌ها، کارایی و تست‌ها بر پایهٔ حالت‌های شکستِ همین پروژه |
| `bors-frontend-ui-guard` | هنگامِ تغییرِ رابط کاربری (چیدمان، تراز جدول‌ها، RTL، ارتفاع) |
| `bors-build-install-guard` | هنگامِ بیلد/نصبِ بسته تا گاردهای موجود (pinِ numpy، بسته‌بندیِ onedir، fallbackها) نشکنند |

قاعدهٔ حاکم بر همه: گاردهای `dev/run_all_tests.py` مرجعِ درستی‌اند؛ تغییر تا وقتی سبز نشوند تمام‌شده نیست.
