# طرح محدود مرحلهٔ ۴ — محاسبه‌گر محور رشد فروش محلی

## دامنه

یک محاسبه‌گر TypeScript خالص برای شاخص ۱ FTS، مطابق `monthly_series`, `ytd_denominator` و `revenue_growth_yoy` در `fts_engine.py`. این مرحله API/UI موجود `/api/fts` را تغییر نمی‌دهد، snapshot را جایگزین نمی‌کند و dependency تازه‌ای ندارد.

## قواعدی که باید عیناً حفظ شوند

- از YTD گزارش تازه استفاده شود؛ مخرج اولویتاً ستون رسمی `ytd_revenue_prev` همان گزارش است.
- فقط اگر آن ستون مثبت نیست، YTD گزارش سال قبل در همان ماه استفاده شود؛ ماه قبل یا مبلغ ماهانه مخرج نیست.
- ورودی باید کامل‌بودن دو فیلتر بیرونی دسکتاپ را اعلام کند: گسترش alias نماد و حذف عنوانِ مربوط به شخصیت حقوقی دیگر. خودِ محاسبه‌گر YTD مثبت، مرتب‌سازی، سقف ۶۰ ردیف و dedupe دوره با برنده‌شدن YTD بزرگ‌تر را اعمال می‌کند.
- کف پیش‌فرض قبولی ۴۰٪ و هدف رشد ۶۰٪ است. قبولی با رشد خام سنجیده می‌شود؛ خروجی درصدی طبق `round(growth, 1)` پایتون به یک رقم اعشار گرد می‌شود.
- قراردادِ ناقص یا دورهٔ قابل‌مقایسهٔ غایب باید `NOT_EVALUATED` بدهد، نه رشد صفر یا رد.

## مرز این برش

`codalStore` هنوز query سریِ تاریخچه با alias/title policy ندارد. تا زمان افزودن و آزمون آن query، محاسبه‌گر تنها ورودیِ صریحاً `DESKTOP_COMPATIBLE` را می‌پذیرد؛ به resolver یا قیف اصلی وصل نمی‌شود. بنابراین هیچ FTS زنده‌ای روی کل Universe ادعا نمی‌شود.

## راستی‌آزمایی و بازگشت

- آزمون‌های واحد برای اولویت مخرج رسمی، fallback همان ماه سال قبل، dedupe دوره، آستانه‌های ۴۰/۶۰، گردکردن هم‌ارز Python و وضعیتِ `NOT_EVALUATED`.
- خروجی‌های موارد آزمون با `ytd_denominator` و `revenue_growth_yoy` پایتون روی ورودی‌های یکسان مقایسه شوند.
- rollback: حذف ماژول محاسبه‌گر، تست آن و همین طرح؛ هیچ migration یا داده‌ای را تغییر نمی‌دهد.
