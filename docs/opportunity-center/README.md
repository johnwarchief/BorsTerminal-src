## لایه‌بندی شواهد

هر ادعای مهم در این مجموعه یکی از این برچسب‌ها را دارد:

| برچسب | معنا |
|---|---|
| **تأییدشده** | در کد، داده یا تستِ همان مبنا دیده شد؛ مسیر و خط ذکر می‌شود. |
| **سنجیده** | عدد با روش و تاریخ مشخص اندازه‌گیری شد. |
| **سند** | در سند موجود آمده و در این مأموریت دوباره سنجیده نشد. |
| **فرضیه/پیشنهاد** | انتخاب طراحی یا فرض کاری است، نه واقعیت تأییدشده. |
| **نامعلوم** | راستی‌آزمایی نشده یا منابع متناقض‌اند. |

منابع وب با تاریخ دسترسی ثبت می‌شوند. ادعای فروشندهٔ محصول از رفتار مستندشده جدا می‌شود. هیچ آستانه یا قاعدهٔ تازه برای FTS اختراع نمی‌شود.

## قیدهای غیرقابل‌عبور

1. منطق FTS بازپیاده‌سازی نمی‌شود؛ مرجع قواعد `docs/جزوه FTS.pdf` و `docs/fts-notes/OWNER_RULINGS.md` است.
2. تعداد استراتژی‌ها ثابت نیست؛ عدد چهار مثال اولیه بود.
3. رتبه‌بندی قابل‌توضیح است و روش‌های ناهمگون به یک امتیاز مبهم تقلیل نمی‌یابند.
4. Backtest مثبت به‌تنهایی اثبات اعتبار یا سودآوری نیست.
5. درخت استراتژی پنج‌صفحه‌ای خارج از محدوده است؛ تغییر یا حذف نمی‌شود.
6. Kronos و مدل‌های پیش‌بینی متعلق به Technical Intelligence‌اند و پیش‌فرض Opportunity Center نیستند.
7. Python فقط مرجع پژوهش، منطق تاریخی یا Oracle تست است؛ Runtime آینده Go است.
8. Prototype مستقل می‌ماند و وارد Runtime تولید نمی‌شود.
9. هیچ داده‌ای از ماشین کاربر خارج نمی‌شود.
10. Approved یعنی مجوز استفاده در کشف فرصت، نه مجوز معاملهٔ واقعی.

## معیار موفقیت نهایی

BorsTerminal باید طرحی منسجم داشته باشد که هم فرصت‌های موجود را پیدا و توضیح دهد، هم بتواند روش‌های تازهٔ کشف را به‌صورت فرضیه ثبت کند، آن‌ها را با استاندارد علمی آزمایش و اعتبارسنجی کند، و فقط استراتژی‌های معتبر را به مجموعهٔ قابل‌استفاده اضافه کند.
