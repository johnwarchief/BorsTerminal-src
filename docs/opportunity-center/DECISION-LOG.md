## گزینه‌های ردشده (با دلیل کوتاه)

| گزینه | چرا رد شد |
|---|---|
| Opportunity-first به‌تنهایی | خطر تبدیل محصول به فید سیگنال و پنهان‌شدن تولید/اعتبارسنجی |
| Research-first به‌تنهایی | فاصله از کار روزانهٔ معامله‌گر؛ ارزش اولیه دیر می‌آید |
| ساخت صفحهٔ جدید خارج از پوستهٔ موجود | پوسته و گروه «کشف فرصت» از قبل وجود دارند؛ بازطراحی سراسری لازم نیست |
| Embed Prototype در `frontend-v2` | نقض ممنوعیت تغییر عملیاتی و ریسک ورود به Runtime |
| استفاده از `main` به‌عنوان مبنا | Stage 3 در `main` نیست؛ توصیف معماری Go ناقص می‌شد |
| بازپیاده‌سازی FTS | تصمیم مالک؛ خطر دو تعریف و واگرایی |
| امتیاز منفرد مرکب | تصمیم مالک؛ پنهان‌کردن ابعاد و غیرقابل‌توضیح |
| انتشار خودکار استراتژی‌های تولیدشده | نقض مرز اعتبارسنجی و تأیید انسانی |
| جست‌وجوی باز/GP به‌عنوان تولید پیش‌فرض | ریسک Overfitting و Data Snooping؛ شواهد Allen 1999 |
| Runtime پایتون | تصمیم مالک؛ معماری هدف Go |
| بک‌تست دقیقه‌ای/تیک در نسخهٔ اول | دادهٔ تاریخی وجود ندارد؛ ادعای بی‌پشتوانه |
| ابر/GPU-first | قاعدهٔ محلی‌بودن؛ هزینه و حریم خصوصی |
| بازارچهٔ استراتژی/سیگنال | تناقض با مدل شواهد و تأیید؛ خطر محصول عمومی و شلوغ |

1. هر تصمیم تازه یک شناسهٔ `OC-D-0NN` می‌گیرد و تاریخ دارد.
2. اگر تصمیم مالک است، متن صریح مالک نقل و تاریخ ثبت می‌شود؛ تصمیم طراحی به‌عنوان تصمیم مالک ثبت نمی‌شود.
3. تصمیم قبلی حذف نمی‌شود؛ ابطال یا جایگزینی با ارجاع ثبت می‌شود.
4. هر تصمیم باید به پرسش باز یا سند مرتبط لینک شود.
