## ۴) یافته‌ها، علتِ ریشه‌ای و اصلاح

شدت: **بالا** = داده/کنترلِ دیدنی می‌رود یا اسکرولِ جعلی؛ **متوسط** = بریدگیِ متن؛
**کم** = عددِ محیطی.

### الف) `whitespace-nowrap` سراسری، `line-clamp-2` را بی‌اثر می‌کرد — **متوسط، رفع شد**
`features/portfolio/components/WatchTable.tsx`: `TD` (سطرِ ۷۳) یعنی
`px-2 py-1 text-start whitespace-nowrap` و ستونِ نام `line-clamp-2` داشت. درِ عمل
 «توسعه سامانه ي نرم افزاري نگين» **۸px** با بی‌«…» بریده می‌شد (`box.h=12`: فقط یک
 خط). اول `break-words` زده شد — بی‌اثر (اندازه‌گیریِ دوباره همان ۸px)؛ بعد رویِ
 `td` گذاشتیم `whitespace-normal` — باز بی‌اثر، چون **دو کلاسِ `whitespace-*` رویِ
 یکِ گره، آخرِ CSS را می‌برند نه ترتیبِ نوشتن**. اصلاحِ نهایی رویِ خودِ `span`:
 `line-clamp-2 block whitespace-normal break-anywhere`.
هزینه: فقط ردیفی که نامش واقعاً دو خط می‌شود بلندتر می‌شود — `row h=37` برایِ هشت
ردیفِ اول دست‌نخورده، `pageScroll` دیدهبان ۱۹۹ → ۲۱۱ (**+۱۲px**).

### ب) ۴ پیکسلِ اسکرولِ جعلی درِ تکنیکال — **بالا، رفع شد**
`features/technical/routes/TechnicalPage.tsx:241` ارتفاعِ کارگاه را
`calc(100dvh-3rem)` (۴۸px) می‌گرفت، درحالی‌که پوسته ۳۶px تاپ‌بار + ۱۶px `py-2`
بردار می‌کند = **۵۲px**. نتیجه درِ **هر دو** viewport `docScroll = +4px` (۱۴۴۰ و
۲۱۶۰) — یعنی اسکرولبارِ بی‌مورد و بریدۀ پایینِ چارت/نوارِ وضعیت. اصلاح: همان
توکنِ موجودِ پوسته `h-[calc(100dvh-var(--pinned-h)-1rem)]` — بی‌عددِ دستی، پس
بلندترشدنِ تاپ‌بار دیگر بی‌سروصدا چارت را نمی‌بُرد. بعد: `docScroll = 0`.

### ج) فهرستِ اعلان‌ها بی‌سقف بود — **بالا، رفع شد**
۱۲۰ ردیف = **۹٬۴۲۳px** اسکرولِ *صفحه* درِ ۲۵۶۰×۱۴۴۰ و ۸٬۸۵۵px درِ ۳۸۴۰×۲۱۶۰؛
هیچ اسکرولرِ داخلی نبود (`scrollables: []`)، پس سرآمدِ «منبع/تازگی» و فیلترها با
اسکرول می‌رفتند. اصلاح با همان الگویِ خودِ برنامه (`tape-scroll`،
`fts-screen-scroll`): صفحه `h-[calc(100dvh-var(--pinned-h)-1rem)]` و `ul`
`flex-1 min-h-0 overflow-y-auto overscroll-contain`. بعد: `pageScroll=0`،
`notice-list 1281/10704` (آخرینِ ردیف با اسکرولِ کوتاه رسیدنی).

### د) برچسبِ بلندِ فیلتر درِ جدولِ سابقۀ نوارِ ابزار — **متوسط، رفع شد**
`shared/components/TapeHistoryPanel.tsx`: درِ ۳۸۴۰×۲۱۶۰ «کد به کد حقوقی به حقیقی»
۵px بریده می‌شد. علت: جدول `table-fixed` است و عرضِ ستون را `<th>` تعیین می‌کند —
`w-[9.5rem]`=۱۵۲px. (نخست `min-w` رویِ `<td>` آزمود شد: **بی‌اثر**، و درِ سند ماند
تا کسی دوباره امتحان نکند.) اصلاح: `<th className="w-[10.5rem] …">`.

### ه) چیزی که «یافته» نیست و صریح ثبت می‌شود
- `overflowX = 0` درِ **همۀ** routeها درِ هر دو viewport — هیچ اسکرولِ افقیِ ناخواسته
  درِ بدنه نیست؛ جدولِ تابلو (۴۴٬۶۸۰px) و جدولِ وضعیتِ بازار (۳٬۷۰۹px) اسکرولرِ
  داخلیِ خودشان را دارند و آخرینِ ردیفشان رسیدنی است ✓
- هدر درِ همه‌جا `position: sticky` است و پس ازِ اسکرولِ انتها می‌ماند ✓
- `.sr-only` (آزمایشگاه موتور) عمداً ۱px و «بریده» است — درِ کاوشگر ازِ الگوریتم
  بیرون کشیده شد، نه درِ کد.
- `/api/index/tedpix?limit=0 → net::ERR_ABORTED`: تنها requestِ شکست‌خورده؛ `useNnData.ts:80`
  همان `AbortSignal` را به `http` می‌دهد و TanStack Query آن را درِ unmount لغو می‌کند —
  یعنی اثرِ جابه‌جاییِ route درِ همان کاوشگر، نه ایرادِ رابط. **علتش را instruments
  نکرده‌ام** (صراحتاً: استنتاج ازِ کد، نه ازِ ردِّپایِ شبکه).
