# نتیجهٔ مرحلهٔ ۴ — محاسبه‌گر محور رشد فروش

## پیاده‌سازی

ماژول خالص `frontend/src/shared/api/local/ftsGrowth.ts` محاسبهٔ محور ۱ را از قواعد دسکتاپ جدا کرده است: انتخاب YTD جاری، اولویت ستون رسمی مقایسه با دورهٔ مشابه سال قبل، fallback فقط به همان ماه سال قبل، محاسبهٔ رشد خام، کف پیش‌فرض ۴۰٪ و هدف ۶۰٪، تبدیل میلیون ریال به میلیارد تومان و گردکردن هم‌ارز `round(value, 1)` پایتون.

سری مرتب و محدود به ۶۰ گزارش می‌شود و برای دوره‌های تکراری، ردیف دارای YTD بزرگ‌تر نگه داشته می‌شود. اگر مخرج هم‌دوره پیدا نشود یا ورودی قرارداد کامل دسکتاپ را تضمین نکند، خروجی `NOT_EVALUATED` است.

## مرز عمدی

محاسبه‌گر به resolver، UI و `/api/fts` وصل نشده و نتیجهٔ آن در قیف یا صفحه نمایش داده نمی‌شود. کد دسکتاپ پیش از محاسبه، هویت/alias نماد و عنوان گزارش را بررسی می‌کند؛ store فعلی Android هنوز query سری با همان قواعد را ندارد. artifact snapshot بررسی‌شده در `_audit/tmp/probe_pkg/mobile_snapshot.db.gz` فقط جدول `instruments` را از جدول‌های مرتبط داشت و جدول‌های `symbol_identity`, `monthly_sales` و `financial_statements` نداشت. تا فراهم‌شدن ورودی دقیق، اعلام نتیجهٔ زنده نادرست خواهد بود.

## راستی‌آزمایی

- `fts-growth-local.spec.ts`: ۷ آزمون موفق؛ اولویت مخرج رسمی، fallback هم‌ماه سال قبل، حذف جانشینی ماه قبل، dedupe، آستانه‌ها، گردکردن Python و سه حالت `NOT_EVALUATED`.
- همان موارد با `fts_engine.ytd_denominator` دسکتاپ مقایسه شدند: مخرج رسمی ۱۰۰، fallback هم‌ماه ۲۵۰٬۰۰۰٬۰۰۰، و حالتِ مخرجِ غایب همگی با خروجی Android سازگارند. درصدهای نمونه نیز ۶۰٫۰٪ و ۴۶٫۰٪ شدند.
- `npx tsc -b --pretty false`: موفق.
- ESLint روی ماژول و تست جدید: موفق.
- اجرای خودِ Android/Capacitor و اجرای قیف FTS هنوز انجام نشده است.

## گام بعدی

پیاده‌سازی query سری در `codalStore` با provenance و عنوان گزارش، به‌همراه حل دقیق و قابل‌راستی‌آزمایی برای هویت نماد/alias. تا وقتی پوشش آن با `monthly_series` دسکتاپ تطبیق نکند، ورودی `DESKTOP_COMPATIBLE` تولید نشود و محاسبه‌گر به API عمومی وصل نشود. پس از آن parity روی گزارش‌های واقعی و سپس محور بعدی انجام شود.

## گیت نهایی

- اجرای کامل `npx vitest run`: ۱۸۴ فایل موفق، ۲ فایل skip؛ ۱۸۷۶ آزمون موفق و ۵ آزمون skip.
- `npx tsc -b --pretty false`: موفق؛ ESLint هدفمند روی دو فایل جدید: موفق.
- `python dev/persian_glyph_guard.py`: چهار بررسی موفق.
- `npm run lint -- --quiet` در کل مخزن با ۴۵۲۸ خطا شکست خورد. خطاها در مسیرهای تغییرنکرده، از جمله assetهای تولیدی Android، `tapeAlgorithms.ts` و `TapeHistoryPanel.tsx` گزارش شدند؛ دو فایل جدید این مرحله با ESLint هدفمند پاک‌اند.
