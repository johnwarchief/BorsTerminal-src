# اسپایکِ `@danfessler/trellis` — سنجش پیش از تصمیم

> وضعیت: **اندازه‌گیری انجام شد، به کد وصل نشد.** طبقِ خواستِ مالک، این فقط
> یک نمونهٔ جداست و دستِ تب‌هایِ اصلی نخورده.
> تاریخِ سنجش: ۱۴۰۵/۰۷/۰۸ (۲۰۲۶‑۰۹‑۳۰) · نسخهٔ سنجیده‌شده: `0.3.0`

## پرسش

آیا trellis می‌تواند جایِ تب‌هایِ اصلیِ برنامه را بگیرد؟ فرضِ اولیه این بود که
سبک است و شاید برنامه را **تندتر** کند.

## روشِ سنجش

نصبِ واقعی در یک پروژهٔ خالی، ساختِ یک ورک‌اسپیسِ دوپنلی
(`Workspace/Stage/Split/Panel/View/ViewType`)، سپس باندلِ مینی‌فای‌شده با
esbuild در حالی که `react`/`react-dom` بیرونی‌اند — یعنی فقط سهمِ خودِ trellis
شمرده شود، چون این دو را پروژه از قبل دارد.

## نتیجه‌ها

### ۱) وابستگی: صفر ✅

```
dependencies      : {}
peerDependencies  : {}
کشیده‌شده        : فقط react، react-dom، scheduler (که پروژه دارد)
رویِ دیسک        : trellis 672K / 9 فایل · trellis-react 92K / 8 فایل
```

این نقطهٔ قوتِ واقعیِ آن است. برخلافِ `@uselayouts/*` که ۸۰ مگابایت
`@hugeicons` می‌کشد، trellis هیچ چیزی اضافه نمی‌کند.

### ۲) هزینهٔ باندل: **+۴۲٫۳ کیلوبایت gzip، یعنی ۲۷٪ رویِ باندلِ اصلی** ❌

| | خام | gzip |
|---|---|---|
| JS باندل‌شده (tree-shake، react بیرونی) | ۱۰۵ KB | **۳۷ KB** |
| `style.css` (اجباری) | ۲۸ KB | **۵٫۳ KB** |
| **جمع** | | **۴۲٫۳ KB** |
| باندلِ اصلیِ فعلیِ برنامه | | ۱۵۵٫۰۹ KB |

فرضِ «سبک است پس تندتر می‌شود» **وارونه درآمد**: این یک‌چهارمِ کلِ جاوااسکریپتِ
برنامه را اضافه می‌کند، در ازایِ چیزی که کاربر امروز هم دارد (تبِ سالم).

### ۳) رویِ رندرِ نرم‌افزاری بد می‌نشیند ❌

در `dist` این‌ها هست: `will-change` ×۳، `backdrop-filter` ×۱، `scale()` ×۳،
`transition` ×۹، `requestAnimationFrame`، `ResizeObserver`.

این‌ها برایِ یک بومِ زوم‌شونده طبیعی‌اند، ولی
`bors_entry._needs_software_rendering()` در همهٔ شاخه‌ها جز «GPUِ اختصاصی پیدا
شد» **True** برمی‌گرداند و بعد `_render_flags()` این‌ها را می‌فرستد:

```
--disable-gpu --use-angle=swiftshader --use-gl=swiftshader
```

یعنی رویِ بیشترِ ماشین‌هایِ هدف، ترکیبِ لایه با CPU انجام می‌شود.
`backdrop-filter` و `scale` رویِ سطحِ بزرگ دقیقاً همان‌جایی است که SwiftShader
می‌افتد. این ریسکِ کندیِ محسوس است، نه تندی.

### ۴) سنِ پکیج: **چهار روز** ⛔

```
منتشرشده : 2026-09-26
آخرین تغییر: 2026-09-28
نسخه‌ها  : 0.1.0 · 0.2.0 · 0.3.0   (سه نسخه در چهار روز)
نگه‌دارنده: یک نفر · مصرف‌کنندهٔ شناخته‌شده: هیچ
```

این بازدارنده‌ترین یافته است. یک پکیجِ چهارروزهٔ پیش‌از‑۱٫۰ با یک نگه‌دارنده،
که API‌اش هفته‌ای یک بار می‌شکند، زیرِ پوستهٔ ناوبریِ یک برنامهٔ **مالیِ زنده**
جایی ندارد. اگر فردا نسخهٔ ۰٫۴ شکل پنل‌ها را عوض کند یا پکیج رها شود، پوستهٔ
برنامه گروگانِ آن است.

### ۵) کار هم آن‌قدرها کم نیست

trellis پنجره‌هایِ داک‌شونده و زوم‌شونده می‌دهد — یعنی جایگزینیِ تب‌ها با آن
فقط عوض‌کردنِ یک کامپوننت نیست: مسیریابی (`react-router`)، بارگذاریِ تنبلِ
صفحه‌ها، و ماندگاریِ چیدمان هر سه باید از نو نوشته شوند.

## داوری

**نه — دستِ‌کم نه حالا.** سه دلیل، به ترتیبِ اهمیت:

1. پکیجِ چهارروزه زیرِ ناوبریِ یک برنامهٔ مالی، ریسکِ زنجیرهٔ تأمین است.
2. ‎+۲۷٪ باندل در ازایِ قابلیتی که کاربر نخواسته بود (خواسته «بهتر شدنِ ظاهر» بود).
3. رویِ SwiftShader که حالتِ پیش‌فرضِ بیشترِ کاربران است، احتمالاً **کندتر** می‌شود.

**اگر روزی دوباره مطرح شد**، شرط‌ها: نسخه ≥ ۱٫۰، دستِ‌کم شش ماه سابقه، بیش از
یک نگه‌دارنده، و سنجشِ FPS رویِ یک ماشینِ واقعیِ بدونِ GPUِ اختصاصی — نه رویِ
دستگاهِ توسعه.

**آنچه به‌جایش انجام شد:** همان حسِ «فضایِ کاریِ مرتب» با کدِ خودمان —
`shared/components/VerticalTabs` (کامیتِ `747d3ef`): هزینهٔ باندل صفر
(۱۵۵٫۰۹ kB بدونِ تغییر)، خالصِ ۶۵ خط کدِ کمتر، و شاخصِ لغزانش فقط یک
`translateY` است که رویِ SwiftShader هم روان می‌ماند.

## بازتولیدِ سنجش

```bash
mkdir /tmp/t && cd /tmp/t && npm init -y
npm i @danfessler/trellis @danfessler/trellis-react
npm i -D esbuild
# نمونهٔ دوپنلی در src/main.tsx بنویس، سپس:
npx esbuild src/main.tsx --bundle --minify --format=esm --jsx=automatic \
  --external:react --external:react-dom --external:react/jsx-runtime --outfile=out.js
gzip -9 -c out.js | wc -c
gzip -9 -c node_modules/@danfessler/trellis/dist/style.css | wc -c
```
