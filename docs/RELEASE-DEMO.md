# ساختِ نسخهٔ دمو

> خواستهٔ مالک: «هر وقت ریلیز گرفتی، اسم/نسخه‌اش با نسخهٔ واقعی فرق کند — مثلاً دمو.»

## کوتاه

برچسب را با یک خط تیره بزن. همین. بقیه خودکار است:

```bash
git tag v1.0.66-demo && git push origin v1.0.66-demo
```

نتیجه:

| | نسخهٔ واقعی | نسخهٔ دمو |
|---|---|---|
| برچسب | `v1.0.66` | `v1.0.66-demo` |
| نامِ برنامه | BorsTerminal Ultimate | **BorsTerminal Demo** |
| پوشهٔ نصب | `…\BorsTerminal Ultimate` | **`…\BorsTerminal Demo`** |
| AppId | `{8F3A2E7C-…}` | **`{4D9E1FA3-…}`** |
| فایلِ ستاپ | `…_Setup_v1.0.66.exe` | `…_Setup_v1.0.66-demo.exe` |
| در گیت‌هاب | ریلیزِ عادی | **پیش‌انتشار** |
| آپدیترِ کاربران | می‌بیند | **نمی‌بیند** |

هر دو می‌توانند هم‌زمان رویِ یک ویندوز نصب باشند و کارِ هم را خراب نکنند.

## دو چیزی که واقعاً مهم است

### ۱) `AppId` — وگرنه دمو نصبِ واقعیِ کاربر را می‌بلعد

Inno نصبِ قبلی را با **`AppId`** می‌شناسد، نه با نام. اگر فقط اسم و نسخه را
عوض می‌کردیم و GUID یکی می‌ماند، نصبِ دمو رویِ نصبِ واقعی می‌نشست، کلیدِ
Uninstall را می‌گرفت و کاربر دیگر راهی به برنامهٔ اصلی‌اش نداشت. پس
`/DDemo=1` هم `AppName` و هم `AppGuid` را عوض می‌کند.

از آن‌جا که `DefaultDirName={autopf}\{#AppName}` است، پوشهٔ نصب هم خودبه‌خود
جدا می‌شود.

### ۲) `prerelease` — وگرنه دمو رویِ همهٔ کاربران پوش می‌شود

آپدیترِ درون‌برنامه‌ای از این نشانی می‌خواند:

```
https://github.com/johnwarchief/BorsTerminal/releases/latest/download/latest.json
```

گیت‌هاب پیش‌انتشار را هرگز «latest» حساب نمی‌کند. پس با پرچمِ
`prerelease=true`، ریلیزِ دمو در صفحهٔ ریلیزها دیده می‌شود ولی به دستِ هیچ
کاربرِ واقعی نمی‌رسد. بدونِ این پرچم، انتشارِ یک بیلدِ دمو یعنی پوش‌شدنِ
`latest.json`ِ دمو رویِ همهٔ نصب‌ها.

## قاعده‌ای که هر دو نیمه از آن پیروی می‌کنند

> برچسبی که بخشِ pre-release سم‌ور دارد (خط تیره پس از عددها) = دمو.

`v1.0.66-demo` ✅ · `v1.0.66-rc1` ✅ · `v1.0.66` ❌ (واقعی)

- `.github/workflows/release.yml` → اگر `$ver -match '-'` آنگاه `/DDemo=1`
- `scripts/publish_github_release.py` → `IS_PRERELEASE = re.match(r"^v?\d+(\.\d+)*-", TAG)`

**این دو باید با هم بمانند.** اگر یکی را عوض کردی، آن یکی را هم عوض کن.

## ساختِ دستی رویِ ویندوز

```powershell
python scripts/build_all.py
& "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" /DAppVersion=1.0.66-demo /DDemo=1 installer\bors_setup.iss
```

## گارد

`dev/installer_identity_v1066.py` (در `dev/run_all_tests.py` ثبت شده)
پیش‌پردازندهٔ Inno را شبیه‌سازی می‌کند و می‌سنجد:

- بیلدِ واقعی هنوز **دقیقاً** `{8F3A2E7C-1B44-4C2E-9A77-0B0B5C0DE001}` است —
  چون اگر این GUID تکان بخورد، ارتقاء برایِ هر کسی که امروز برنامه را نصب
  دارد می‌شکند.
- بیلدِ دمو GUID و نام و کلیدِ Uninstallِ جدا دارد.
- `APP_ID` در `api/update.py` با `AppId`ِ نصب‌کننده یکی مانده.

این گارد لازم است چون ISCC فقط رویِ ویندوز اجرا می‌شود؛ خرابیِ این اشتقاق در
CI کامپایل می‌گیرد و فقط سرِ کاربر معلوم می‌شود.

## آنچه عمداً انجام **نشد**

`APP_VERSION` در `bors_config.py` دست نخورد و همان `1.0.65` ماند. نسخه از
برچسبِ گیت می‌آید (`ISCC /DAppVersion=$ver`)، پس دست‌زدن به فایل فقط یک جایِ
دیگر برایِ ناهمگام‌شدن می‌ساخت. `APP_VERSION` به کلیدِ کشِ اسکرینر
(`screener.py:222`) و `DisplayVersion`ِ رجیستری (`update.py:207`) هم وصل است
و بی‌دلیل تکانش نمی‌دهیم.
