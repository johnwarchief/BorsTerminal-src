# طرح اجرایی محدود — دادهٔ بنیادی Codal محلی در Android

**تاریخ:** 2026-10-18
**دامنه:** یک برش عمودی برای گزارش فعالیت ماهانه؛ بدون تغییر موتور/فرمول FTS و بدون سرویس مرکزی.

## شواهد معماری موجود

- Android backend پایتونی ندارد. resolver مسیرهای FTS را از JSONهای پخته‌شده می‌خواند و جدول‌های SQLite snapshot فاقد `monthly_sales` و `financial_statements` هستند.
- `localData.ts` با `sql.js` snapshot را در حافظه باز می‌کند و Cache API را برای بسته‌های پایدار به کار می‌گیرد؛ نوشتن ردیفیِ Codal وجود ندارد.
- دسکتاپ `codal_fetcher.scrape_monthly_report()` گزارش فعالیت ماهانه را از `datasource` تعبیه‌شده در HTML استخراج می‌کند. قواعد انتخاب ستون دوره/جمع، مقادیر سال جاری/سال قبل و حجم فروش در همان parser مرجع است.
- یک درخواست جست‌وجوی محدود برای نماد خساپا و یک درخواست گزارش واقعی، از میزبان توسعه با HTTP 200 پاسخ داده‌اند. این سنجش از گوشی Android اجرا نشده و دسترسی گوشی را اثبات نمی‌کند.

## دامنهٔ پیاده‌سازی

1. snapshot دست‌نخورده مانده است. ماژول مستقلِ دیتابیس جانبی از همان موتور `sql.js` استفاده می‌کند و artifact را در Cache API جداگانه نگه می‌دارد.
2. schema نسخه‌دار شامل `codal_documents` برای URL/شناسه/عنوان/منبع/HTML خام/hash/زمان دریافت/وضعیت parse، `monthly_sales` برای مقادیر استخراج‌شده و دوره، و `codal_sync_state` برای آخرین تلاش/موفقیت و خطای شبکه است.
3. کلید یکتای اطلاعیه `tracing_no` است؛ upsert تراکنشی از ردیف تکراری جلوگیری می‌کند و hash محتوای SHA-256 تغییر محتوای همان اطلاعیه را قابل‌شناسایی می‌کند. گزارش اصلاحی همان شناسه را به‌روز می‌کند.
4. پیش از نوشتن artifact، تراکنش SQLite بسته و `integrity_check` و نسخهٔ schema بررسی می‌شوند؛ سپس یک `Cache.put` روی کلید مستقل انجام می‌شود. فایل snapshot هدف این نوشتن نیست. خطای ذخیره‌سازی با adapter تزریقی آزموده شد؛ اتمی‌بودن و ماندگاری Cache API در WebView واقعی هنوز آزمون نشده است.
5. مسیرهای `POST /api/codal/monthly-sales/sync?symbol=...` و `GET /api/codal/monthly-sales?symbol=...` اضافه شده‌اند. همگام‌سازی فقط یک نماد و یک صفحهٔ گزارش ماهانه را می‌خواند؛ درخواست‌ها سریالی و با فاصلهٔ حداقل ۱٫۷ ثانیه هستند. 403، 429، خطای شبکه و شکل HTML ناشناخته وضعیت صریح می‌گیرند؛ retry خودکار داخل همان تلاش انجام نمی‌شود.
6. آزمون‌ها با `sql.js` واقعی schema، مهاجرت، upsert و شکست ذخیره‌سازی را می‌سنجند. parser اندروید روی HTML واقعی Codal با `scrape_monthly_report()` دسکتاپ تطبیق داده شده است. parity موتور FTS و نمایش نتیجهٔ نهایی در UI به مرحلهٔ بعد موکول است.

## معیار اتمام این برش

- مهاجرت تکراری بی‌اثر باشد و نسخهٔ schema ناشناخته بدون overwrite رد شود.
- ذخیرهٔ مجدد همان اطلاعیه تکراری نسازد؛ گزارش اصلاح‌شده مقدار قبلی را جایگزین کند.
- فیلدهای ناموجود `null` بمانند؛ هیچ مقدار صفر یا نتیجهٔ FTS استنباط نشود.
- درخواست زنده فقط وقتی موفق تلقی شود که Codal واقعاً پاسخ داده، parser قرارداد را تشخیص داده و تراکنش ذخیره‌سازی تأیید شده باشد.
- این مرحله ادعای اجرای محلی قیف FTS یا parity با دسکتاپ ندارد.

## نتیجهٔ اجرا

در اجرای زندهٔ 2026-10-18، جست‌وجوی محدود نماد خساپا و گزارش `TracingNo=1599533` هر دو از میزبان توسعه HTTP 200 دادند. پاسخ HTML گزارش 917,053 بایت بود. parser دسکتاپ و parser TypeScript اندروید هر دو دورهٔ `1405/06/31` و این مقادیر را برگرداندند: فروش ماهانه 83,814,250، فروش تجمیعی 364,877,646، فروش تجمیعی دورهٔ مشابه 490,556,472، حجم ماهانه 17,174، حجم تجمیعی 66,067 و واحد «دستگاه». مقدار فروش ماهانهٔ دورهٔ مشابه در خود گزارش خالی بود و هر دو parser آن را `null` نگه داشتند.

این آزمون شبکه از گوشی اجرا نشده است. ذخیره‌سازی با SQLite واقعی و adapter حافظه آزموده شد؛ فعال‌سازی Cache API در WebView، مصرف مسیر از UI، دریافت‌های TSETMC در Android و اجرای موتور/قیف FTS هنوز راستی‌آزمایی نشده‌اند.
