## ۱) ساختارِ چارت: ۴ صفحه ← ۱۳ دستهٔ سطح‌اول

### صفحهٔ ۱ — `F: بنیادی`
پنج شاخص، بی‌سطحِ میانی.

### صفحهٔ ۲ — `T: تکنیکال` ← **سه شاخهٔ سطح‌اول**

```
تکنیکال T
├─ سیگنال خرید
│   ├─ تایم هفتگی روند نزولی ──→ reject
│   ├─ تایم هفتگی روند خنثی  ──→ reject
│   └─ تایم هفتگی روند صعودی
│       ├─ تایم روزانه صعودی → استراتژی پولبک · استراتژی جت
│       ├─ تایم روزانه نزولی → استراتژی فیبوناچی · CHOOCH
│       └─ تایم روزانه خنثی  → ورود در آخرین کف/سقف · کف دوقلو
├─ سیگنال فروش
│   ├─ سقف دوقلو
│   ├─ سروشانه مشابه CHOCH
│   ├─ سقف سوم (تایم هفتگی ۱۰٪ **و** تایم روزانه ۵٪ نزدیک خط روند)
│   └─ واگرایی مقاومتی (سقفِ بالاتر در نمودار، سقفِ پایین‌تر در RSI)
└─ حد ضرر
    ├─ ۵٪ زیر آخرین کف روند صعودی
    ├─ شخص نوسانگیر: MA=14، تشکیل یک کندل کامل زیر MA
    └─ شخص روندگیر: خرید پله‌ای و حد ضرر ۵٪ زیر نقطه ورود
```

«نزولی» و «خنثی» هرکدام جعبهٔ `reject` **جداگانه** دارند.

### صفحهٔ ۳ — `S: SELECTION` ← **پنج شاخهٔ سطح‌اول**

```
S: SELECTION
├─ انتخاب سبک معامله → نوسانگیر · روندگیر
├─ رصد جریان نقدینگی
│   ├─ بررسی وضعیت بازار در TRADERS ARENA
│   │   ├─ ارزش معاملات >۲۰ همت مساعد · <۱۰ همت نامساعد
│   │   ├─ تعداد و درصد مثبت/منفی (صف فروش) — ۸۰٪ منفی = هنوز فرصت ورود
│   │   ├─ نمودار ارزش سفارش‌های خرید و فروش
│   │   ├─ نمودار نمادهای مثبت و منفی
│   │   ├─ نمودار سرانهٔ خرید و فروشِ معاملات خرد
│   │   ├─ نمودار تعداد صف‌های خرید و فروش
│   │   └─ ورود و خروج پول (ایده‌آل: خروج از درآمد ثابت، ورود به سهام)
│   ├─ بررسی صنایع: خلاصهٔ معاملات صنایع بورس
│   └─ سهام برگزیده (مرتب‌سازیِ «درصد آخرین» و «ورود پول»)
├─ حجم معاملات
│   ├─ نوسانگیر → بررسی حجم مشکوک (۳× میانگین ماهانه) → volum, MA lenght=21
│   └─ روندگیر  → بررسی حجم معاملات → ورود در قیمت ارزنده
├─ الگوهای تابلوخوانی
│   ├─ نوسانگیر → الگوی ساعت · خروج از باکس رنج
│   └─ روندگیر  → کف روبی · خشک کردن
└─ فیلتر
    ├─ نوسانگیر → ساعت (TVOL>1، قابلِ تغییر به ۳ یا ۵) · جت · حجم مشکوک
    └─ روندگیر  → کف روبی · نقطه زنی (ورود در کف سوم یا پنجم)
```

### صفحهٔ ۴ — **چهار درختِ مستقل**

```
مهندسی معکوس → ۱- تابلوخوانی (فیلتر حجم مشکوک · الگوی ساعت · کف روبی)
                ۲- تکنیکال
                ۳- بنیادی

مدیریت سرمایه → سقف ۷۰٪ (جنگی ۲۰٪ ±۱۰٪) · وزن سبد با حداکثر ضرر ۲۰٪±۱۰٪
                صندوق‌های ETF · پوشش ریسک با آپشن
                نوع حد ضرر در نوسانی و روندی
                ورود و خروج پله‌ای + ابزار کمکی (RSI=7 هفتگی · MA=100 روزانه · MA=52 هفتگی)
                رصد و تحلیل مداوم پورتفوی · تناسب دیدگاه با بورس ایران

اصول یک پورتفوی بهینه بورسی → سهام دلاری/ریالی · بزرگ/کوچک
                              تولیدی/غیرتولیدی · صندوق‌های سرمایه‌گذاری

استراتژی → ساعت شنی (هفتگی MA=52 و RSI=5)
           جت (عبور از سقف تاریخی/مقاومت استاتیک + کندل تثبیت، مهلت ۳ روز)
           نقطه زنی (ورود در کف سوم یا پنجم)
```

## ۲) یافتهٔ اصلی: گراف **هیچ‌یک از ۱۳ دستهٔ سطح‌اول را ندارد**

```
signal_buy · signal_sell · stop_loss              → ۰
sel_style · sel_liquidity · sel_volume
  · sel_patterns · sel_filter                     → ۰
rev_engineering · money_mgmt
  · portfolio_principles · strategy_group         → ۰
```

گراف امروز یک **شبکهٔ تخت** است: یک هابِ مرکزی (`fts_core`) که مستقیم به
۴۹ برگ وصل می‌شود. برگ‌ها تقریباً همه درست‌اند و فرمول‌هایشان هم (حسابرسیِ
`TREE-CHART-AUDIT-1.0.66.md`)، ولی **شکلِ درخت بازتولید نشده**.

خواستهٔ مالک این بود: «چهار چارت را در یک نمودارِ درختی نشان بدهم.» چیزی که
هست، فهرستِ برگ‌هاست نه درخت. این دقیقاً همان «دقیق نیست» است.

## ۳) دو مسئلهٔ جانبی که از تصویر روشن شد

1. **«خشک کردن» جای اشتباهی است.** در چارت فرزندِ *روندگیر* زیرِ «الگوهای
   تابلوخوانی» است. در گراف داخلِ `tape_final_filters` با برچسبِ «فیلترهای
   نهایی (خشک کردن)» ادغام شده — یعنی با دستهٔ «فیلتر» که در چارت شاخهٔ
   جداگانه‌ای است قاطی شده.

2. **«نوسانگیر / روندگیر» چهار بار تکرار می‌شود** (انتخاب سبک، حجم معاملات،
   الگوهای تابلوخوانی، فیلتر). گراف این را با `presets: ['swing','trend']`
   رویِ یال‌ها رمزگذاری کرده که رمزگذاریِ معقولی است، ولی در تصویر این یک
   **سطحِ واقعیِ درخت** است نه صفتِ یال.

## ۴) چرا این کار بزرگ است

چیدمانِ گراف **کاملاً دستی** است: ۵۰ جفت مختصاتِ `x`/`y` ثابت در کد. افزودنِ
یک طبقهٔ سلسله‌مراتبی یعنی بازمحاسبهٔ همهٔ آن‌ها. کارِ درست این است که چیدمان
از خودِ ساختار مشتق شود (درختِ لایه‌ای)، نه اینکه ۶۳ مختصات دستی نگه‌داری
شود.

**پیشنهاد برای دورِ بعد:**
1. ۱۳ گرهٔ دسته اضافه شود و یال‌ها از هاب به دسته و از دسته به برگ برود.
2. مختصاتِ دستی با یک چیدمانِ لایه‌ایِ محاسبه‌شده جایگزین شود (عمق × ترتیب).
3. «خشک کردن» از `tape_final_filters` جدا و زیرِ «الگوهای تابلوخوانی/روندگیر»
   برود.
