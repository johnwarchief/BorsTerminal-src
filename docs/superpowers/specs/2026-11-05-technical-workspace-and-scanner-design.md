# طراحی — میزکار تکنیکال ۲ و اسکنرِ واحد رویدادها

**تاریخ:** ۲۰۲۶-۱۱-۰۵ · **وضعیت:** تأییدشده توسط مالک · **شاخه:** `integration/4axes-main-2026-11-03`
**پیش‌نیاز:** موج الگوها (`f1425f79`..`998d3c7a`) — موتور ۱۲ الگو و آمار موجود است.
**مرجع تصمیم‌ها:** `docs/BorsTerminal-Desktop-Migration-Decisions.md` (بندهای ۱۲.۳۶، ۱۲.۳۷، ۱۲.۳۸.۴، ۱۲.۳۹) و دفتر تاریخی.

## ۱. مسئله
مالک دید که موج قبل یک تبِ «الگوها»ی موازی ساخت، در حالی که تبِ «اسکنر الگوها» از قبل وجود داشت؛
میزکار بازطراحی نشده بود؛ دقت و نمایشِ الگوها کافی نبود؛ و کانال/واگرایی/پولبک به‌صورت خودکار
روی چارت دیده نمی‌شدند. هدف این مأموریت: **یک میزکارِ بازطراحی‌شده با یک اسکنرِ واحد که هنگام
لودِ نماد، همهٔ رویدادهای مهم را می‌سنجد و مهم‌ترین‌ها را در نگاه اول نشان می‌دهد.**

## ۲. تصمیم‌های قطعیِ مالک
1. **درصد الگو = هر دو، با برچسب جدا:** نرخ بردِ تاریخی (۱/۳/۵ کندل، نمونه و بازهٔ ویلسون — هم‌جنس
   با اسکنر فعلیِ کندلی) **و** کیفیتِ هندسیِ شکل (۰–۱۰۰). هیچ‌کدام جای دیگری را نمی‌گیرد.
2. **چیدمان:** سبک TradingView — چارت مرکز، نوارِ فعالیت، ریلِ راست، پنلِ پایینیِ جمع‌شونده، نوارِ بالا.
3. **فهرست الگو:** ۲۶ نوع با پذیرشِ پله‌ای (ردهٔ ۱ = ۱۹ الگو با پذیرش کامل؛ ردهٔ ۲ = ۷ کم‌بسامد با برچسب). عددِ «۲۲» در گفت‌وگو اشتباهِ شمارش بود؛ فهرستِ زیر ملاک است.
4. **معیار دقت:** تطبیق با قواعدِ منبع + داوری بصری (پذیرش: صفر الگوی جعلی روی نمونهٔ داوری).
5. **نمایش:** برجسته‌سازی هوشمند — یک رویدادِ اصلی در هر خانواده روی چارت، بقیه در فید.

## ۳. معماری اطلاعات (میزکار)
```
┌ Topbar: symbol │ timeframe │ adjustment(3=عملکردی) │ chart type ┐
├ ActivityBar ┬──────────── ChartStage ────────────┬ InspectorRail ┤
│ chart      │  klinecharts + event overlays       │ layers        │
│ scanner    │                                     │ active event  │
│ indicators │                                     │ rules         │
│ settings   │                                     │               │
├────────────┴──────────── EventFeed (collapsible) ┴───────────────┤
│ tabs: رویدادها | ۵۰ نماد | اندیکاتورها | لبه آماری | اسکنر       │
└──────────────────────────────────────────────────────────────────┘
```
- **ActivityBar:** آیکن‌های SVG (همان ستِ `ui/icons.tsx`)، ۴۰px، یک لهجه برای حالتِ فعال.
- **ChartStage:** همان `KLineChartWrapper` + overlayهای فعلی؛ فقط یک overlayِ رویدادها اضافه می‌شود.
- **InspectorRail (۲۸۰px):** لایه‌های روشن/خاموش، کارتِ رویدادِ اصلی (نوع، وضعیت، نرخ برد ۱/۳/۵ +
  نمونه + بازه، کیفیت هندسی، منبعِ قاعده، دکمهٔ «قواعد»).
- **EventFeed (پایین، جمع‌شونده):** فیدِ رویدادها با فیلترِ خانواده/نوع؛ ستون‌ها: خانواده، نوع، وضعیت،
  نرخ برد، نمونه، کیفیت؛ کلیک = فوکوس روی چارت. تبِ «الگوها»ی موجِ قبل **حذف** و محتوایش اینجا ادغام می‌شود.
- تب‌های موجود (۵۰ نماد/اندیکاتورها/لبه آماری) حفظ می‌شوند؛ فقط جای‌شان عوض می‌شود.

## ۴. مدلِ رویداد و اسکنر
```ts
export type EventFamily = 'pattern' | 'channel' | 'divergence' | 'pullback';
export interface ChartEvent {
  id: string;                 // `<family>:<kind>:<anchorIndex>:<fingerprint>`
  family: EventFamily;
  kind: string;               // PatternKind | channel mode | divergence type | 'pullback' | 'breakout'
  direction: 'bullish' | 'bearish' | 'neutral';
  status: 'forming' | 'confirmed' | 'invalidated';
  anchor: PatternPoint;
  quality: number;            // ۰–۱۰۰ هندسی، نه احتمال
  winRate: { h1: number | null; h3: number | null; h5: number | null };
  samples: number;
  formation: number | null;   // ۰..۱ تاریخی (الگوها)؛ UI ×۱۰۰
  interval?: [number, number];
  evidence: { ruleRef: string; source: 'classic' | 'telegram' | 'existing-engine' };
  draw: EventDrawing;         // خطوط/نواحی/برچسب برای overlay
}
export interface ScanResult {
  at: number; symbol: string; timeframe: string; adjustmentMode: number; bars: number;
  events: ChartEvent[]; primary: Partial<Record<EventFamily, string>>; // id رویدادِ برجسته هر خانواده
}
```
- **زمانِ اسکن:** یک effect در `KLineChartWrapper` بعد از آماده‌شدن `bars` (همان سریِ **تعدیل عملکردی**
  که چارت رسم می‌کند)؛ با تغییر نماد/تایم‌فریم/تعدیل دوباره اجرا می‌شود؛ با identity یکسان، رد می‌شود.
- **پنجره‌ها:** اسکنِ رویدادها روی ۵۰۰ کندلِ آخر؛ نمونه‌های تاریخیِ نرخ برد روی کلِ سریِ بارشده
  (حداکثر ۱۵۰۰ کندل). بودجهٔ اسکن < ۵۰ms برای ۵۰۰ کندل، بدونِ long task؛ نتیجه در استور (`scanResult`)
  و متادیتای `bars/adjustmentMode/timeframe` برای صداقتِ نمایش.
- **رتبه‌بندیِ برجستگی:** `forming` > `confirmed`، سپس کیفیت، سپس تازگی anchor؛ برای هر خانواده یک برنده.
- **بدونِ نگاه به آینده:** فقط پیوتِ تأییدشده (پارامترهای `PATTERN_CONFIG`)، نه کندلِ در حال تشکیل.

## ۵. موتور الگو — دقت و فهرست
### ردهٔ ۱ (۱۹ الگو، پذیرش کامل)
دوقلوی سقف/کف · سر و شانه ± · سه‌قلوی سقف/کف · پرچم صعودی/نزولی · پنانت ·
مثلث صعودی/نزولی/متقارن · مستطیل · گُوهٔ صعودی/نزولی · کاپ‌هندل و معکوس · گردشدنِ سقف/کف.
### ردهٔ ۲ (۷ کم‌بسامد، بهترین‌تلاش + برچسب «کم‌بسامد»)
دیاموند سقف/کف · پهن‌شوندهٔ سقف/کف · جزیره‌ای · سه‌قلهٔ صعودی (three rising peaks) · سه‌قلهٔ نزولی (three falling peaks).
> شمارشِ رده‌ها در سند نهاییِ قواعد (یک فایل `docs/patterns/rulebook.md`) با صفحه/مرجع هر قاعده می‌آید
> و همان در «قواعد» UI رندر می‌شود؛ هیچ آستانه‌ای بیرونِ `PATTERN_CONFIG` نمی‌ماند.

- **الزامات دقت:** هر الگو با فیکسچرِ مثبت/منفی/مرزی؛ حذفِ الگوهای هم‌مرز با اثرانگشت؛ ابطال با بافر؛
  کفِ ارتفاع؛ اسکنِ کلِ تاریخچه (نه فقط دم)؛ پیوتِ تأییدشده.
- **داوری بصری:** ۱۵ نماد × ۲ تایم‌فریم (روزانه/هفتگی) با اسکرین‌شات و شمارشِ «جعلی» و «جاافتاده»؛
  پذیرشِ ردهٔ ۱: جعلی = ۰ و هر الگو با قاعدهٔ منبع قابلِ توضیح.

## ۶. واگرایی RSI
- RSI(۱۴) روی بستهٔ تعدیل‌شدهٔ همان سری؛ پیوت‌های قیمت و RSI هر دو **تأییدشده**.
- چهار نوع: **عادی صعودی/نزولی** و **مخفی صعودی/نزولی**، در سقف و کف.
- تلورانس: قیمت ۰.۵×ATR، RSI ۲ واحد؛ پنجرهٔ ۱۲۰ کندل؛ حداقلِ فاصلهٔ دو پیوت ۵ کندل.
- رسم: خطِ روند روی قیمت + برچسبِ نوعِ فارسی؛ مقدار RSI و دو پیوت در کارت. پنلِ RSI جدا ساخته نمی‌شود.
- بدونِ نگاه به آینده؛ واگراییِ ناتمام گزارش نمی‌شود.

## ۷. کانال و پولبک/شکست
- **کانال:** از موتورِ موجود (`MultiModeChannel`: رگرسیون/ریتست/دانچیان)؛ اسکنر بهترین حالت را با
  برازشِ R² روی ۱۲۰ کندل انتخاب می‌کند و همان را برجسته می‌کند؛ مقدار R² و شیب در کارت.
- **پولبک/شکست:** از `advancedTradingIndicators` موجود؛ آخرین رویدادِ تأییدشده در فید و یک مورد برجسته.
- هیچ فرمولِ تازه‌ای جز قواعدِ همین دو موتور اضافه نمی‌شود.

## ۸. نمایش و انیمیشن
- overlayِ رویدادها: حداکثر **چهار شکلِ برجسته** (یکی per family) + یک برچسبِ فارسی هرکدام؛
  بقیه فقط در فید. رنگ از پالتِ تم‌آگاه (کمینه ۴.۵:۱).
- **انیمیشن (web-animation-design):** ورودِ کارتِ ریل و چسبِ برچسب: `opacity` + `translateY(6px)` در
  ۲۰۰ms با یک منحنی (`cubic-bezier(0.22,1,0.36,1)`)، یک‌بار؛ هیچ loop/pulse؛ خطوطِ canvas بدونِ
  انیمیشنِ layout. `prefers-reduced-motion` → فقط fade.
- unslop: کفِ ۱۲px، آیکنِ SVG، شبکهٔ ۴px، شعاعِ تو‌در‌تو، سلسله‌مراتب با اندازه/رنگ نه bold.

## ۹. تست و پذیرش
- واحد: فیکسچرِ هر الگو (مثبت/منفی/مرزی)، واگرایی (۴ نوع + منفی)، کانال/پولبک (برجستگی)، مدلِ رویداد.
- یکپارچه: اسکنِ نماد → `ScanResult` با primary درست؛ فید و ریل با fixture؛ کلیک = فوکوس.
- عملکرد: اسکنِ ۵۰۰ کندل < ۵۰ms؛ بدون long task هنگام لود؛ سنجشِ ۱۳۶۶ و ۱۹۲۰.
- بصری: ۱۵ نماد × ۲ تایم‌فریم، هر دو تم؛ شمارشِ جعلی/جاافتاده؛ اسکرین‌شاتِ نگاه اول.
- رگرسیون: اسکنرِ فعلی و اندیکاتورهای موجود دست‌نخورده؛ دوقلو بیت‌به‌بیت.

## ۱۰. فازبندی
A) دقتِ موتور + ردهٔ ۲ + ادغامِ تبِ «الگوها» در اسکنر (بدونِ تغییرِ چیدمان).
B) بازطراحی میزکار (TradingView) + unslop.
C) اسکنِ کانال/پولبک/واگرایی + مدلِ رویداد + برجسته‌سازی و انیمیشن.
D) داوری بصری و پذیرشِ نهایی (۱۳۶۶/۱۹۲۰، هر دو تم، جعلی=۰).

## ۱۱. خارج از دامنه
کرونوس، پورتِ کاتالوگ تلگرام، اجرای سفارش، تغییرِ موتورِ داده، و هر تغییر در FTS/بنیادی.

## ۱۲. ریسک‌ها
- **شلوغی چارت:** بودجهٔ چهار شکل + فید؛ برچسب فقط برای رویدادِ برجسته.
- **کارایی اسکن روی سری‌های بلند:** پنجرهٔ ۵۰۰ کندل و اسکنِ O(n·pivots)؛ سنجشِ اجباری.
- **الگوهای کم‌بسامد:** برچسبِ ردهٔ ۲ و پذیرشِ نرم‌تر؛ پنهان‌سازی نمی‌شوند.
- **هم‌پوشانی موتورها:** اولویتِ خانواده در رتبه‌بندی و اثرانگشتِ مشترک.
- **تفاوتِ اپِ نصبی و dist:** پذیرش روی distِ همین checkout و ذکرِ نسخه.
