# Technical Indicator Intake

این پوشه محل جمع‌آوری اندیکاتورها و ابزارهای تکنیکال برای بررسی و احتمالاً ادغام در BorsTerminal است.

## مسیرها

- `inbox/`: هر چیز تازه‌ای که پیدا می‌کنید، قبل از بررسی.
- `reviewed/`: مواردی که ایجنت بررسی کرده و نتیجه/محدودیت‌هایشان مستند شده است.
- `implemented/`: مواردی که واقعاً در BorsTerminal پیاده‌سازی و با تست تأیید شده‌اند.

## روند پیشنهادی

1. فایل اصلی، لینک منبع و اسکرین‌شات را تا حد امکان بدون تغییر در `inbox/` قرار دهید.
2. برای هر اندیکاتور یک پوشهٔ جدا بسازید؛ نام پوشه کوتاه و انگلیسی باشد، مثل `rsi-divergence/`.
3. اگر فقط لینک یا تصویر دارید، همان را همراه توضیح کوتاه اضافه کنید؛ لازم نیست فرمول را از قبل بدانید.
4. ایجنت باید منبع، مجوز استفاده، فرمول، پارامترها، نیازهای داده، repainting/look-ahead، رفتار روی کندل ناقص و سازگاری با معماری نمودار BorsTerminal را بررسی کند.
5. تا پیش از بررسی و تأیید تست‌ها، فایل‌های `inbox/` کد فعال برنامه محسوب نمی‌شوند.

## نکات مهم

- کد ناشناس را مستقیم اجرا نکنید؛ مخصوصاً اسکریپت‌ها و فایل‌های اجرایی دانلودشده از کانال‌ها.
- رمز، توکن، کوکی، اطلاعات حساب یا دادهٔ خصوصی را داخل این پوشه نگذارید.
- منبع اصلی و مجوز/شرایط استفاده را ثبت کنید. وجود یک اسکریپت عمومی به معنی اجازهٔ کپی یا بازتوزیع آن نیست.
- ادغام نهایی باید از دادهٔ معتبر BorsTerminal استفاده کند و با تست‌های رگرسیون و در صورت امکان مقایسه با Rahavard انجام شود.

## قرارداد استفاده در توسعهٔ موتور تکنیکال و الگوها

این پوشه صرفاً آرشیو جانبی نیست؛ منبع ورودی اجباری برای توسعهٔ بعدی موتور تکنیکال و الگوهاست. پیش از ساخت هر اندیکاتور/الگوی جدید، ایجنت باید:

1. `implemented/` را برای کد و تست موجود بررسی و همان قابلیت را reuse کند؛
2. `reviewed/` را برای تحقیق، فرمول، parity، محدودیت و نتیجهٔ قبلی بخواند؛
3. `inbox/` را به‌صورت کامل و با hash محتوا ممیزی کند؛
4. `docs/Indicator/` قدیمی و کدهای فعال در `frontend-v2/src/features/technical/` و `backend-go/internal/indicators/` را با آن تطبیق دهد؛
5. فقط پس از اثبات نبود قابلیت معادل، شکاف را به‌صورت محدود پیاده‌سازی کند.

مرجع تریاژ فعلی `TELEGRAM-CATALOG-TRIAGE-2026-11-03.md` است: ۹ Overlay پیاده‌شده در آن ثبت شده و سه کاندید بعدی S/R Retest Breakout، Wedge/Channel Detector و Order-Block Scoring هستند. پیش از هر کار جدید، وضعیت واقعی این موارد در کد و تست‌ها دوباره بررسی شود؛ عنوان موجود در کاتالوگ به‌تنهایی اثبات پیاده‌سازی یا صحت نیست.

برای هر فایل، تصمیم و دلیل آن ثبت شود: `reuse`, `port`, `adapt`, `research-only`, `defer` یا `reject`. فایل‌های باینری EX4/EX5 منبع قابل‌ممیزی نیستند: اجرا، decompile یا انتقال مستقیم آن‌ها به برنامه مجاز نیست. MQL4/MQL5 نیز باید از نظر نوع واقعی (Indicator، Expert Advisor، Script یا Library) و مجوز بررسی شود. قیدهای MPL-2.0، CC BY-NC-SA 4.0 و موارد بدون مجوز باید پیش از هرگونه کپی/توزیع رعایت شوند.

**قاعدهٔ توسعه:** ابتدا استفاده و تکمیل دارایی‌های موجود؛ نه بازنویسی از صفر. خروجی هر مورد باید با دادهٔ واقعی BorsTerminal، مبنای تعدیل مشخص، تست کندل ناقص و ضد-Repaint/Look-ahead اعتبارسنجی شود.
