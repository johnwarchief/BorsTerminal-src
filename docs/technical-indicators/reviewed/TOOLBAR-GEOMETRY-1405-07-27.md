## علتِ واقعی (سه تلاشِ نافرجام پیش ازِ این)

درِ `frontend/src/features/technical/styles/tvTheme.css` دو قاعده با نیتِ «بی‌فضایِ
مرده و بی‌اسکرولِ اضافه» نوشته شده بود:

1. `… header, … [class*='toolbar'] { overflow: visible !important; flex-wrap: nowrap !important; min-width: 0 !important }`
   — `overflow: visible !important` قاعدۀِ `overflow-x:auto`ِ خودِ نوار را بی‌اثر
   می‌کرد (محاسبهٔ واقعی: `visible`)، پس ردیف نمی‌توانست اسکرول شود؛
2. `… [class*='toolbar'] > * { min-width: 0; flex: 0 1 auto }`
   — تک‌تکِ کنترل‌ها اجازهٔ فشرده‌شدنِ زیرِ عرضِ متنشان را داشتند و متنِ `nowrap`
   از جعبه بیرون می‌زد و رویِ کنترلیِ کناری می‌نشست.

این توضیح می‌دهد چرا سه قاعدۀِ `flex-shrink:0` که پیش‌تر آزمودم هیچ تغییری ندادند
(آزمونِ زنده: `node _audit/chart_toolbar_fix_experiment.js`، پنجِ گزینه، همه
۵ همپوشانی) — آن قاعده‌ها با `!important` می‌باختند.

## درمان

`header.nn-top-toolbar` ازِ آنِ بلِ فراگیر جدا شد: درِ عرضِ باریک، ردیف **تا می‌خورد**
(`flex-wrap: wrap`، `height:auto`) و هیچ فرزندی زیرِ `max-content` فشرده نمی‌شود.
منوهایِ بازشو همچنان `overflow: visible` دارند، پس هیچ پاپ‌آپِ بریده‌ای ساخته نشد.

## هزینه‌ای که باید دانست

درِ ۱۳۶۶x۷۶۸ نوار دو‌خطی می‌شود و ارتفاعِ پنِ قیمت از ۴۳۹ به ۴۰۲ پیکسل
می‌نشیند (−۳۷). درِ ۱۶۰۰x۹۰۰ تک‌خطی می‌ماند. رفتارِ پنهان/نمایشِ محورها
پس ازِ این تغییر دوباره سنجش شد و هر ششِ حکم سبز است
(`node _audit/chart_axis_visibility.js`: پن ۸۸۳×۴۰۲، محورِ قیمت ۴۵→۰→۴۵،
محورِ زمان ۳۲→۰→۳۲). اگر به‌جای تاخوردن، کوتاه‌کردنِ برچسب‌ها (آیکن +
tooltip) ترجیحِ مالک است، همان هارنس تغییر را اندازه می‌گیرد.
