# ران‌بوکِ پایشِ بازشدنِ بازار — یکشنبه 2026-10-18

> این سند دستورِ کارِ **فردا** است، نه ادعای انجام‌شده. هیچ‌یک از بند‌هایِ پایین درِ این اجرا
> رویِ دادهٔ زندهٔ TSETMC سنجیده نشده است؛ وضعیتِ هر بند درِ گزارشِ پایانی با برچسبِ
> `NOT_RUN` / `NOT_PROVEN` آمده است.

## ۰) چرا این سند جدا است

پایشِ واقعیِ بازشدنِ بازار نیازمندِ سه چیزی است که درِ یک اجرایِ کوتاه‌عمرِ همین امروز
موجود نیست: زنده‌ماندنِ فرایند تا ساعتِ شروعِ نشست، دسترسی به مسیرِ خروجیِ شبکهٔ TSETMC، و
هماهنگی با System 1 برایِ سرویسِ :8000. پس ابزار و فرمان‌ها اینجا آماده‌اند و اجرا به فردا واگذار می‌شود.

## ۱) پیش‌نیازِ System 1 (بی‌این، سنجشِ زنده معنا ندارد)

| # | چیزی که باید راستی‌آزمایی شود | فرمانِ بررسی | اگر نشد |
|---|---|---|---|
| ۱ | سرویسِ واقعی رویِ :8000 از **همین چکاوت** پاسخ می‌دهد، نه از ورک‌تریِ دیگر | `netstat -ano \| findstr :8000` → PID؛ سپس `python tools/perf_winproc.py <pid>` و `git -C <cwd-that-process> rev-parse HEAD` (cwdِ پردازه از `wmic process where processid=<pid> get executablepath`) | پایش را `NOT_RUN` بنویس؛ دادهٔ چکاوتِ دیگر را مدرکِ این کد معرفی نکن |
| ۲ | حلقه‌هایِ دریافتِ TSETMC/CODAL **روشن**‌اند (`BORS_NO_FETCH_LOOPS` ست نشده باشد) | `GET /api/sync/status` و mtime/`ts` درِ `<checkout>/market_sync.json` — باید داخلِ نشست تازه شود | اگر `last_sync` کهنه است، زنجیرۀ تازگی از همان حلقه می‌شکند؛ سنجشِ پایین‌دست فقط کرانِ بالا می‌دهد |
| ۳ | egressِ بورس باز است (خطای `10013/WSAEACCES` از 2026-10-15 برطرف شده) | لاگِ سرویس + `GET /api/chart/فولاد` که `degraded` نداشته باشد | هر ادعای «تازگیِ داده» را `NOT_PROVEN` بنویس |
| ۴ | restartِ :8000 **فقط** با هماهنگیِ System 1 | — | خودسر restart نکن؛ این اقدامِ ماست نه آن‌ها |

بی‌بندِ ۲ و ۳، هیچ عددی از این ران‌بوک «تازگیِ داده درِ نشستِ واقعی» را ثابت نمی‌کند.

## ۲) آماده‌سازی (پیش از ۰۸:۴۰، ساعتِ تهران)

```bash
# ۲-الف) فقط گیتِ آفلاین، سرورهایِ dev بسته — تا کدِ فردا با کدِ سنجش‌شده یکی باشد
python dev/run_all_tests.py
python dev/version_anchor_guard.py        # باید "VERSION ANCHOR GUARD OK" بدهد

# ۲-ب) هشِ سورسِ همان کدِ کاری که بالا می‌رود (درِ گزارش بنویس)
python -c "import hashlib;print(hashlib.sha256(open('api/funnel.py','rb').read()).hexdigest())"
git rev-parse HEAD

# ۲-ج) یک پوشهٔ خروجیِ تازه برایِ هر پنجره (خدشه‌ای را بازنویسی نکن)
mkdir -p _audit/perf/mo-2026-10-18-a
```

قیدها: حلقهٔ دریافتِ اضافی نساز؛ polling موازی نساز؛ فقط یک کلاینت به :8000 وصل باشد
(ابزار خودش با کد ۳ رد می‌کند، مگر `--allow-other-clients` که فقط آگاهانه است)؛ `--clock` رویِ
:8000 مجاز نیست و ابزار آن را رد می‌کند.

## ۳) اجرا (۰۸:۳۰ تا ۱۲:۴۵)

دو ترمینال، به همین ترتیب؛ اولِ نمونه‌گیر چون منفعل است و درخواستی نمی‌فرستد.

```bash
# ۳-الف) نمونه‌گیرِ منفعل: CPU/RAMِ پردازهٔ پورت، کلاینت‌ها، mtime/اندازۀ بانک، آفستِ ساعت
python tools/perf_market_open_sampler.py --port 8000 \
  --out _audit/perf/mo-2026-10-18-a/sampler.jsonl \
  --watch <checkout>/market.db --watch <checkout>/market.db-wal \
  --watch <checkout>/market_sync.json \
  --start-at 08:30 --until 12:45 --top-every 60
```

```bash
# ۳-ب) پایشِ مرورگری: فقط درخواست‌هایِ خودِ برنامه، مسیرِ واقعیِ کاربر
node tools/perf_market_open_monitor.mts --url http://127.0.0.1:8000 \
  --out _audit/perf/mo-2026-10-18-a \
  --start-at 08:40 --until 12:40 \
  --journey market:900,master:300,market-status:300,fundamental:120,market:600
```

توقفِ زودهنگام: فایلِ `STOP` کنارِ خروجی، یا Ctrl+C. پنجرهٔ بعدی را با پوشهٔ تازه (`-b`, `-c`)
و ترجیحاً پس از هر رویدادِ مهم (سازۀ اول، میانهٔ نشست، پایان) بگیر؛ بی‌پوشۀ تازه، دو اجرا در هم می‌رود.

## ۵) معنایِ هر عدد (تا کسی همان را «تأخیرِ شبکه» نخواند)

همهٔ زمان‌ها epochِ ساعتِ **همین ماشین** (تهران)، مگر خلافش گفته شود.

| فیلد | چیست | چه چیزی **نیست** |
|---|---|---|
| `t0` | لحظۀ `fetch` درِ صفحه | زمانِ ساختِ داده |
| `ttfb` (`th − t0`) | رسیدنِ هدرها | زمانِ رندر |
| `dur` (`tj − t0`) | انتظارِ کلاینت تا پایانِ `JSON.parse` | «داده رویِ صفحه» |
| `render` (`paint − tj`) | نخستین فریمِ پس از نخستین جهشِ DOM بعدِ tj | زمانِ سرور |
| `lag_cycle` (`tj − last_sync`) | کهنگی نسبت به پایانِ سیکلِ همگام‌سازِ سرور | کهنگی نسبت به بورس |
| `lag_exchange` | کهنگی نسبت به `d_even + h_even` (ساعتِ آخرین معاملۀ TSETMC) | تأخیرِ خالص — کجیِ ساعتِ بورس با این ماشین اندازه‌گیری‌پذیر نیست، پس این **کرانِ بالایِ کهنگی** است |
| `lag_asof` / `lag_computed` | سنجش‌ها ازِ بدنهٔ فانل (`as_of`) و mstat (`computed_at`) | زمانِ واقعیِ داده درِ بورس |
| `payloadAgeS` / `cache_age_sec` | عمرِ **محاسبه** (پاسخِ کش‌شده) | عمرِ **داده** |
| `x-cache` | `MISS`/`HIT`/`STALE` رویِ پاسخِ فانل | مدرکِ تازگیِ داده |
| `mstat`/`mtime` درِ `sampler.jsonl` | تنها نشانِ «بانک واقعاً نوشته شد» | نشانهٔ رسیدنِ دادهٔ تازه |
| `clock_offset_ms` | آفستِ ساعتِ ماشین نسبت به NTP، درِ آغاز و پایانِ نمونه‌گیر | مجوزِ مقایسهٔ عدد با ثانیه‌شمارِ بورس — بی‌این، هر `lag` تا همان اندازه خطا دارد |

## ۶) زنجیرۀ تازگی (هر حلقه را جدا ثبت کن)

`منبعِ داده (h_even/d_even)` → `دیتابیس یا snapshot جاری (mtime، last_sync)` → `پاسخ API (as_of/computed_at)` →
`کلاینت (tj)` → `DOM/UI (paint، برچسبِ تازگی)`

برایِ هر حلقه بنویس: عدد، واحد، منبعِ عدد، و اگر دسترسی لازم نبود `NOT_PROVEN`. آستانهٔ «FROZEN»
ساخته **نمی‌شود**: فقط «دادۀ امروز نیست» (`d_even ≠ تاریخِ نشست`) و «هیچ تغییرِ `rev`ی درِ پنجره دیده نشد»
گزارش می‌شوند، به‌همراه بلندترین بازۀ بی‌تغییری.

## ۷) تفسیرِ نتایجِ دانسته از پیش (تا سنجشِ فردا غافلگیری نباشد)

- **سازۀ نخستِ فانل پس ازِ بالا آمدنِ سرویس:** درِ ریگِ آفلاین، `POST /api/funnel`ِ اول بینِ
  74 تا 118 ثانیه معطلِ اسکنِ سنگینِ گرمایِ استارت‌آپ شد. این زمانِ موتورِ قیف نیست؛ اگر فردا
  کاربر درِ ۰۹:۰۰ همان را دید، ریشۀ آن همین است. بی‌هماهنگی با System 1، راه‌حلِ «گرم‌کردنِ
  زودتر/خارجِ مسیرِ درخواست» پیشنهاد نشود.
- **`X-Cache: HIT` رویِ فانل** یعنی بدنهٔ هشت‌ثانیه‌ایِ کش‌شده سرو شده، و کاربر هیچ‌وقت دادهٔ
  کهنه به‌عنوانِ تازه نمی‌بیند (`cached_for_ms` رویِ پاسخِ کش هست؛ برچسبِ UI آن را معنا می‌کند).
- **`/api/chart/…`** ممکن است `degraded: true` و `historyRepairScheduled: true` ببرد: یعنی CDN
  نرسید و مسیر به `price_history` افتاده و برایِ **همان یک نماد** یک ترمیمِ تاریخچه درِ پس‌زمینه
  رفته است. این رفتارِ خودش است؛ درِ سنجشِ برابریِ خروجی، این مسیر جزوِ `EXTERNAL_PATHS` است و
  حکم نمی‌سازد.

## ۸) پس ازِ اجرا

گزارشِ خام را نگه دار (`events.jsonl`, `sampler.jsonl`, `analysis.json/md`) و فقط ازِ همان عدد
درِ گزارشِ نهایی بنویس. اگر بندِ ۱ رد شد، درِ گزارشِ نهایی بنویس «پایشِ زنده انجام نشد، چون…»
و ادعای عملکردِ نشست را به همان سنجش‌هایِ آفلاین محدود کن.
