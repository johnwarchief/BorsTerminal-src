## ۶) مرزِ فنیِ «آماده‌سازیِ فقط‌خواندنی» (چیزی که این دور *ساخته نشد*)

ترکیبِ ایمنِ مسیرِ مرورگری، آن‌قدر که شواهد اجازه می‌دهد:

1. پنجره را خودِ کاربر وارد می‌کند (همین حالا درِ `execution_connect` ساخته شده)؛ هیچ
   تایپ/کلیکی ازِ سویِ برنامه نمی‌شود.
2. اگر روزی تزریقی افزوده شود، فقط **خواندن**: تطبیقِ اینکه نماد/قیمت/حجمِ رندرشده با قصدِ
   ما یکی است، و گرم‌کردنِ چیدمانِ فرم تا T−0.
3. مرزی که شواهد تعیین می‌کنند: درِ `chrome.scripting` بی‌`world:'MAIN'` (و معادلش درِ
   CDPِ isolate) state درونیِ React و پاسخِ HTTP دیده نمی‌شود؛ پس «آنچه DOM نشان می‌دهد»
   تضمین می‌شود، نه «آنچه مدلِ صفحه خواهد فرستاد». ادعایِ دوم ساختن = حدس.
4. هیچ `.click()`/`dispatchEvent` رویِ هیچ کنترلِ ارسالی، درِ هیچ حالتی — چون مرجعِ شمارهٔ ۲
   نشان داد همان یک خط، دو ارسالِ زنده برایِ یکِ قصد می‌سازد.

## ۶)الف) مشاهدۀ زمانِ اجرا درِ این دور (تازۀ همان شب)

§۴ مأموریت خواست نشانیِ صفحۀ رسمیِ ورود «درِ زمانِ اجرا» بررسی شود. یکِ درخواستِ
فقط‌خواندنی، بی‌هیچ مدرکِ احرازی و بی‌هیچ درِ سفارش:

| نشانی | نتیجه |
| --- | --- |
| `https://d.easytrader.ir/` | ۲۰۰، بی‌بازگشت به میزبانِ دیگر، `text/html`، title = `EasyTrader`؛ **هیچ `<form>`، هیچ `password`، هیچ `captcha` درِ پاسخِ اولیه** ⇒ پوستۀ SPA است و ورودِ کاربر سمتِ کلاینت ساخته می‌شود |
| `https://d.easytrader.ir/login` | ۲۰۰، همان پوسته (رویتهایِ سمتِ کلاینت) |
| `https://easytrader.ir/` | ۲۰۰، بدونِ بازگشت به `d.` |

سه پیامد:

۱) BLOCKEDِ بندِ ۱ از §۶ *نصفه* باز می‌شود: میزبانِ صفحۀ ورودِ کاربر الان شاهدِ زنده دارد
   (`d.easytrader.ir`) و این میزبان باِ میزبانِ API (`api-mts.orbis.easytrader.ir`) فرق دارد —
   همان دلیلی که `login_hosts()` درِ `execution_connect` عمداً از `allowed_hosts()` جداست.
   اپراتور می‌تواند باِ `BORS_EXECUTION_CONNECT_HOSTS=d.easytrader.ir` پنجره را رویِ همان
   میزبانِ تأییدشده باز کند.
۲) هرچه پس ازِ تایپِ رمز می‌گذرد (نشانیِ submit، قالبِ MFA/CAPTCHA، رفتارِ ۴۰۱) همچنان
   **مشاهده نشده** است؛ دیدنِ آن نیازمندِ ورودِ واقعیِ خودِ کاربر است، نه درخواستِ برنامه.
۳) چون صفحۀ ورود SPA است، «آماده‌سازیِ فقط‌خواندنی» (§۶ بند ۲ و ۳) نمی‌تواند باِ خواندنِ
   HTMLِ نخست انجام شود؛ باید پس ازِ رندرِ صفحه و باِ تزریقِ isolate خوانده شود — همان
   محدودیتی که مرجعِ پنجم (§حوزہ ۳) باِ عددِ خطِ کد نشان می‌دهد: ازِ دنیایِ isolate پاسخِ HTTP
   و state درونیِ فریم‌ورک دیده نمی‌شود.
