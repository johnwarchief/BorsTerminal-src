# مشخصات تنظیمات قابل‌سفارشی‌سازی FTS

> **وضعیت:** این سند ابتدا قرارداد طراحی بود؛ در شاخهٔ پیاده‌سازی ساعت‌شنی، کنترل‌های UI، اعتبارسنجی API و اتصال موتور اضافه شده‌اند و تست آفلاین قرارداد نیز نوشته شده است. تا تأیید اجرای تست‌ها/CI و merge، این قابلیت release-verified محسوب نمی‌شود.

## هدف

کاربر باید بتواند پارامترهای اجرایی FTS را از رابط برنامه انتخاب و تغییر دهد؛ نه اینکه برای تغییر RSI، آستانه، جهت MA یا حدهای غربالگری فایل کد را ویرایش کند. تغییر پارامتر باید در همه مسیرهای مصرف‌کننده FTS یکسان اثر کند: تحلیل تک‌نماد، بنر تکنیکال، قیف، مستر و درخت. هیچ صفحه‌ای نباید نسخه محلی/ثابت همان قاعده را جداگانه محاسبه کند.

مرجع قواعد پایه همچنان PDFهای FTS و رأی‌های صریح مالک است. «قابل‌سفارشی‌سازی» بودن به معنی تغییر پنهانی متدولوژی مرجع نیست: رابط باید مقدار پایه FTS، مقدار سفارشی کاربر و اثر فعال آن‌ها را شفاف نشان دهد.

## رأی جاری ساعت شنی

- پیش‌فرض دوره RSI ساعت شنی: **۷**؛ این تصمیم صریح مالک در رأی شماره ۲۴ است و ابهام قبلی RSI=5 در چارت در برابر RSI=7 در جزوه را برای مقدار پیش‌فرض می‌بندد.
- RSIهای مستقل دیگر، از جمله RSI(14) لایه واگرایی/خروج، از این تغییر اثر نمی‌گیرند.
- آستانه اشباع فروش ۳۰ فقط پیش‌فرض اجرایی فعلی است؛ چون از دو PDF به‌عنوان حد قطعی اثبات نشده، باید در UI قابل‌تغییر و به‌عنوان پارامتر پیاده‌سازی برچسب‌خورده باشد، نه «عدد قطعی جزوه».
- شرط جهت قیمت نسبت به MA52 از PDFها به‌قدر کافی قابل استخراج نیست. تنظیم باید گزینه‌های **زیر MA52 / بالای MA52 / بدون شرط جهت** داشته باشد. مقدار آغازین زیر MA52 فقط برای حفظ رفتار کنونی است و نباید قانون قطعی منبع معرفی شود؛ کاربر می‌تواند آن را تغییر دهد.
- MA52 ساعت شنی همچنان روی داده هفتگی است و در صورت کمبود ۵۲ کندل هفتگی، خروجی باید UNKNOWN / insufficient data باشد؛ تنظیم RSI نباید باعث شود میانگین کوتاه‌تر به نام MA52 جا زده شود.

## قرارداد داده تنظیمات

تنظیمات پایه در مسیر موجود تنظیمات FTS (FTS_CONFIG_PATH و GET/POST /api/fts/config) قرار می‌گیرند. برای پارامترهای ساعت شنی این کلیدها تعریف شوند:

| کلید | نوع | پیش‌فرض | محدوده/مقادیر معتبر | تفسیر |
|---|---|---:|---|---|
| **hourglass_rsi_period** | integer | **7** | 2 تا 100 | دوره RSI هفتگی ساعت شنی، مستقل از RSI خروج |
| **hourglass_rsi_oversold** | number | **30** | 5 تا 50 | سقف RSI برای وضعیت اشباع فروش؛ مقدار پیش‌فرض اجرایی، نه عدد قطعی PDF |
| **hourglass_ma52_position** | enum | **below** | below، above، either | جهت قیمت نسبت به MA52؛ either یعنی MA52 برای زمینه محاسبه شود اما جهت آن گیت فعال‌سازی نباشد |

قواعد قرارداد:

1. کلیدهای جدید در نبود فایل یا تنظیم قدیمی به پیش‌فرض بالا مهاجرت می‌کنند؛ نبود کلید نباید باعث خطا، صفر فرض‌کردن یا رد اشتباه نماد شود.
2. بک‌اند مرجع نهایی اعتبارسنجی و مقدار مؤثر است. مقدار نامعتبر باید با نام همان فیلد به UI برگردد؛ مقدار ناقص یا نامعتبر نباید بی‌صدا ذخیره شود.
3. GET /api/fts/config مقدار مؤثر را برمی‌گرداند و POST پس از ذخیره همان مقادیر نرمال‌شده را برمی‌گرداند. Reset باید همه کلیدها را صریحاً به مقدار پیش‌فرض برگرداند.
4. تنظیمات پس از restart باقی می‌مانند. کلید کش تحلیل تک‌نمادی شامل دوره RSI، آستانه اشباع و حالت MA52 است؛ تغییر تنظیم خروجی قدیمی را reuse نمی‌کند. کش‌های React Query فرانت هم پس از save باطل می‌شوند.
5. پاسخ موتور باید مقدار مؤثر را گزارش کند: rsi_period، rsi_oversold، ma52_position_mode، مقدار RSI محاسبه‌شده و نتیجه شرط. نام فیلد نباید به‌اشتباه weekly_rsi5 بماند وقتی دوره فعال ۷ یا مقدار سفارشی دیگری است. alias قدیمی فقط در صورت نیاز به سازگاری، موقت و deprecated بماند.
6. این سه پارامتر فقط ساعت شنی را کنترل می‌کنند؛ RSI(14) خروج، وتوی روند هفتگی، منطق بنیادی پنج شاخص و رأی‌های ثابت مالک نباید از این تنظیمات ارث ببرند.

## تجربه کاربری

تنظیمات تکنیکال باید از تب تکنیکال و مسیرهای FTS به‌سادگی پیدا شود؛ در نسخه نخست می‌توان کنترل‌ها را در دراور موجود FTS قرار داد، اما عنوان/بخش آن باید «تنظیمات FTS» باشد نه صرفاً تنظیمات کدال.

- دوره RSI: ورودی عدد صحیح/اسلایدر با مقدار فعلی، دامنه و دکمه بازنشانی.
- آستانه اشباع: ورودی عددی با توضیح اینکه عدد پیش‌فرض ۳۰، فرض اجرایی قابل‌تغییر است.
- موقعیت نسبت به MA52: انتخاب سه‌حالته زیر/بالا/بدون شرط جهت؛ توضیح روشن درباره اثر هر انتخاب.
- دکمه‌های «ذخیره»، «بازگشت به پیش‌فرض» و «لغو تغییرات ذخیره‌نشده».
- حالت بارگذاری، خطای اعتبارسنجی درون‌فیلدی و اعلام موفقیت/شکست واقعی ذخیره.
- نمایش «پیش‌فرض FTS» در کنار «تنظیم سفارشی»؛ کاربر نباید تصور کند مقدار سفارشی، قاعده جدید جزوه است.

نسخه اول می‌تواند یک پیکربندی فعال برای هر نصب داشته باشد. قرارداد API باید طوری بماند که پروفایل‌های نام‌دار در آینده بدون کپی‌کردن تنظیمات بین صفحه‌ها اضافه شوند؛ فعلاً لازم نیست چندپروفایلی را به‌صورت ناقص پیاده کنیم.

## معماری و منبع حقیقت

- یک قرارداد typed/validated در بک‌اند و یک schema متناظر در فرانت داشته باشیم؛ نام‌ها، نوع‌ها و دامنه‌ها باید همسان باشند.
- همه موتورهای FTS تنظیم فعال را از یک مسیر بخوانند. UI نباید پارامتر را فقط برای نمایش محلی اعمال کند.
- هر خروجی تحلیل باید مبنای محاسبه را آشکار کند و برای پارامترهای سفارشی، مقادیر مؤثر را به‌صورت metadata گزارش دهد.
- اگر داده برای محاسبه کافی نیست، null/UNKNOWN برگردد؛ کمبود داده با سیگنال منفی یا «غیرفعال» اشتباه نشود.
- تنظیمات عمومی بازار/شرکت و تنظیمات تکنیکال ساعت شنی از یک کلید یا یکسان‌سازی اتفاقی نوع داده استفاده نکنند.

## سابقه و شکاف‌های زمان نگارش اولیه

در زمان نگارش نسخهٔ اولیهٔ این سند، `api/chart.py` ساعت‌شنی را با RSI(5)، شرط ثابت RSI <= 30 و `weekly_close < MA52` ارزیابی می‌کرد و خروجی را `weekly_rsi5` می‌نامید. شاخهٔ پیاده‌سازی این PR اکنون مقدار دوره/آستانه/حالت MA52 را از `fts_thresholds.json` می‌خواند، آن‌ها را در API اعتبارسنجی می‌کند، در پنل موجود FTS قابل‌انتخاب می‌سازد و metadata مؤثر را همراه خروجی برمی‌گرداند. فیلد `weekly_rsi5` برای سازگاری موقتاً باقی می‌ماند و همان RSI محاسبه‌شده با دورهٔ فعال را می‌دهد؛ مصرف‌کنندگان جدید باید از `weekly_rsi` و `rsi_period` استفاده کنند. این تغییرات هنوز نیازمند اجرای واقعی تست‌ها/CI هستند.

## مواردی که همچنان باید جداگانه پیگیری شوند

- اختلاف MA14 در این SPEC باقی است: منبع یک کندل کامل شامل سایه‌ها زیر MA14 را می‌گوید، اما کد دو بدنهٔ متوالی می‌سنجد.
- گیت هفتگیِ قطعی FTS، قواعد بنیادی و دیگر رأی‌های مالک تحت این تنظیمات تغییر نمی‌کنند.

## آزمون‌های پذیرش

1. نصب تازه و فایل تنظیمات قدیمی بدون کلیدهای ساعت شنی، به‌طور پایدار 7 / 30 / below را گزارش می‌کند.
2. ذخیره RSI period=7، سپس تغییر به ۹، خروجی موتور را در RSI هفتگی و metadata تغییر می‌دهد؛ RSI(14) خروج دست‌نخورده می‌ماند.
3. تغییر آستانه اشباع فروش و هر سه حالت MA52 نتیجه قابل تکرار ایجاد می‌کنند؛ either فقط گیت جهت را حذف می‌کند، نه نیاز به داده کافی برای MA52.
4. مقدارهای خارج از محدوده و enum ناشناخته رد می‌شوند و فایل تنظیمات قبلی خراب نمی‌شود.
5. پس از ذخیره، صفحه‌های بنر، قیف، مستر و درخت به یک پاسخ واحد/به‌روز می‌رسند؛ خروجی cache شده با تنظیم قبلی نمایش داده نمی‌شود.
6. Restart برنامه تنظیمات را نگه می‌دارد و Reset تمام پارامترهای ساعت شنی را به 7 / 30 / below بازمی‌گرداند.
7. تست parity ثابت می‌کند default/schema فرانت، default بک‌اند، پاسخ endpoint و خروجی موتور هم‌خوان هستند.
