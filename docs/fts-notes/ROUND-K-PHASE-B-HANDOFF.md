## قراردادِ جدید (تصمیمِ مالک، رأیِ باز)

«تمام تحلیل‌های تکنیکال FTS باید بر اساس تایم‌فریم روزانه انجام شوند» —
مبنایِ هر داور، تریگر، ورود، خروج، هشدار، امتیاز و `tech_status` = کندلِ روزانۀ
کاننیکال. هفتگی/ماهانی فقط فقط اطلاعِ‌رسان، نه وتو، نه امتیاز، نه ردّ.

## جا‌هایِ دقیقِ درگیر (api/chart.py مگر با خواندنِ خودِ تابع دست نزن)

| مورد | جایِ فعلی | آنچه باید عوض شود |
|---|---|---|
| وتویِ هفتگی | `weekly` درِ `_fts_status_block` (`vetoed`) و `FTS_STATUS_PRIORITY` خانهٔ `weekly_veto` | از اولویتِ داوری حذف؛ `weekly_context` اطلاعِ‌رسان بماند |
| روندِ D/W/M | `_fts_trend_state` / ماتریسِ سه‌تایم | «روندِ FTS» = روندِ روزانه؛ W/M فقط context |
| ساعتِ شنی | ریسامپلِ هفتگی + MA52 هفتگی + RSI5 هفتگی | مبنایِ کندل باید روزانه شود؛ پارامترها از جزوه |
| غربگر | `tech_status` از همان `status.code` | بعدِ حذفِ وتو خودکار درست می‌شود — سنجشِ دوباره |
| موتورِ دوم | `engineFtsLayers.ts` فقط رندر | هیچ داوریِ تازه‌ای اینجا ساخته نشود |

## آنچه مالک باید بگوید (اختراع نکنیم)

۱) ساعتِ شنی رویِ سریِ روزانه: MA و RSI با چه عدد و دوره‌ای؟ جزوه فقط «MA52 و
RSI5» را درِ همان ب contextِ هفتگی نوشته. اگر جزوه عددِ روزانه ندارد: همان ابهام
بماند و درِ UI capability اعلام شود — پیاده‌سازیِ حدسی نسازیم.
۲) پس از حذفِ وتویِ هفتگی، متنِ وضعیتِ FTS چه اولویتی بخواند؟ (باقیِ زنجیره
مستند است: Hard Stop → Confirmed Exit → Current Entry Trigger → Warning →
Context → No active signal → Insufficient data)

## تست‌هایِ اجباریِ PHASE B (هنوز نوشته نشده‌اند)

- سنجشِ هر داور (Jet, CHoCH, Point Hunt, Fib, Double Bottom, Range Break,
  Hourglass, MA14, خروجِ L1–L4, `tech_status`): همان نماد با کندلِ روزانه ⇒
  داوری از سریِ روزانه بیاید.
- سنجشِ قوی‌تر: فقط contextِ هفتگی/ماهانی را عوض کن و کندلِ روزانه ثابت بماند ⇒
  هیچ خروجیِ داوری (تریگر، وضعیت، امتیاز، reject) عوض نشود. این تست باید
  کنترلِ منفی داشته باشد: با وتویِ فعلی باید قرمز شود.
- FTS رویِ همان سریِ تعدیل‌شدهٔ کاننیکال که چارت می‌رسمد (قدمِ PHASE A این را برایِ
  هر دو مسیر عوض کرد؛ `analysis_basis` حالا `*-adjusted` / `*-raw` را می‌گوید).
  گاردِ `dev/fts_series_basis_v1036.py` سه حالت را می‌سنجد.
