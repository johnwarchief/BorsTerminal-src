## ۴) قیدِ سختِ معماری برایِ تب‌ها: state امروز سراسری است

- نمادِ انتخابی **یک** عدد برایِ کلِ برنامه است: `shared/stores/symbolStore.ts`
  با کلیدِ `bors-symbol` (+ `bors-symbol-recent`, `bors-symbol-pinned`) درِ
  localStorage. صفحات `params.symbol ?? stored` را می‌خوانند. پس «دو نماد درِ دو
  تبِ مستقل» بی‌ تغییرِ این store ممکن نیست — یا state نماد باید per-tab شود، یا
  مسیر باید منبعِ حقیقت باشد و store فقط حافظۀ «آخرین نماد» بماند. **این تصمیمِ
  فاز یک است، نه اینجا.**
- فیلترهایِ تابلو هم سراسری‌اند (`tapeStore.ts`، کلیدِ
  `bors_tape_filter_config_v2`).
- هیچ store ای «تب» را نمی‌شناسد؛ هیچ فایلِ موجودی `tabId` ندارد.

## ۵) مشکلاتِ UX که ازِ همین جدول می‌خوانم (نه ازِ سلیقه)

1. دو قابلیتِ اجرا (سفارش و ربات) بی‌مسیر، بی‌ورودیِ ناوبری، و درِ پایینِ صفحۀ
   دیگرند ⇒ «پیدا کردنِ قابلیت» همان مشکلی است که مالک نوشته است.
2. `/engine-lab` و `/notifications` درِ ناوبری نیستند ⇒ کاربر آن‌ها را تصادفی
   کشف می‌کند.
3. سه «دیده‌بان» جدا معنایِ یکِ کلمه‌اند: `/watch`، `WatchlistSection` درِ
   `/portfolio`، و `SidebarWatchlist` درِ نوارِ کنارِ تکنیکال ⇒ همان واژه، سه جا.
4. تنظیمات همه مودال‌اند (UserSettings، فیلترهایِ نوار، چارت، FTS) ⇒ هیچ‌کدام
   درِ تاریخچۀ URL نمی‌مانند و درِ تبِ تازه قابلِ بازگشت نیستند.
5. مسیرِ `'' → /master` یعنی «خانه» همان قیف است؛ با افزودنِ تب، «خانه» باید
   معنایِ تازه‌ای پیدا کند (بندِ ۳ مأموریت: New Tab).
