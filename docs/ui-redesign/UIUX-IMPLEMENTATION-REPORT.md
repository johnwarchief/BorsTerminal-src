### C۵) نقصِ کشف‌شدہ درِ کارِ خودم وِ رفعش

نخستین اجرایِ سنجشِ زنده سه عددِ غلط داد وِ یکِ رفتارِ بد:
1. `[role="tab"]` بی‌دامنه، تب‌هایِ FtsDock را هم می‌شمرد ⇒ «۱۳ تب» وِ «بعدِ reload ۱۳ تب» دروغِ سنجش بود، نه نقصِ رابط. حالا همه‌جا `[data-shell="workspace-tabs"] [role="tab"]`.
2. نشانۀِ `/master` را غلط گرفته بودم (`master-breadcrumb` بی‌نماد render نمی‌شود) ⇒ ۱۶.۹ ثانیه به‌عنوانِ «زمانِ ورودِ master» ثبت شده بود. نشانۀِ درست `fts-funnel-workspace` وِ زمانِ واقعی ۴۶۴ms (پیش) / ۵۶۰ms (پس).
3. دکمۀِ `+` باِ قاعدۀِ «همانِ مسیر ⇒ همانِ تب» بی‌صدا عملِ تکراری می‌کرد. حالا `openTab(path, symbol, {forceNew:true})` برایِ `+` وِ قاعدۀِ dedupe فقط برایِ پیوندهایِ «بازکردنِ نماد» (باِ دوِ آزمودنیِ جدا).
4. «۱ متنِ بریده» درِ `/market-status` وِ `/market` خطایِ سنجش بود: `SPAN.sr-only` باِ `clip:rect(0,0,0,0)` وِ عرضِ ۱px **عمداً** پنهان است. حالا الگویِ پنهانِ عمدی (`.sr-only`، عرض ≤ ۱px، `clip`/`clip-path` صفر) ازِ آشکارسازِ «بریدگیِ ناخواسته» بیرون است؛ هرِ دو بیلد `clip=0` می‌دهند.
5. شمارشِ `/api/` درِ دورِ اول بی‌معنا بود (نه صفحۀِ اپ): نه صفحۀِ گرم درِ یکِ tab، پشتِ سرِ هم ⇒ سه مسیر `api=0`. حالا هرِ route درِ contextِ تازه باِ نشستِ ورودِ جدا خوانده می‌شود (cold-start) وِ محدودیت‌هایِ باقی‌ماندۀِ روش درِ §C۳ نوشته شده.
6. سناریویِ تب درِ contextِ تازه، `start` را گم می‌کرد: پیامِ پس ازِ ورود، اپ را بهِ `/master` می‌بَرَد وِ اگرِ سنجش ازِ آنِ چرخشِ hash جلوتر بیفتد، اولینِ سطرِ سناریو تبِ اشتباه را ثبت می‌کند. حالا صبرِ شرطی (`waitTitle`) وِ `hash` درِ خودِ سطرِ شاهد ثبت می‌شود.
7. شاهدِ پیش/پس بی‌هویت بود: هرِ دوِ فایلِ JSON یکِ `base` (همانِ URL) داشتند وِ ازِ رویِ خودِ فایل نمی‌شد ثابت کرد کدامِ بیلد سرو شده. حالا `buildLabel` وِ `bundle` (همانِ `assets/index-*.js` که مرورگر واقعاً دانلود کرده) درِ هرِ artifact ثبت می‌شود؛ درِ سه فایلِ کامیت‌شده: `index-BzFJmp4W.js` (پیش) وِ `index-CAvPwOch.js` (پس + تکرار).
