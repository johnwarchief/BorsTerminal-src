# BorsTerminal Multi-Agent System

بستهٔ کامل سیستم چند-ایجنتی که توسعهٔ این پروژه را اداره می‌کند.
هدف: روی **هر ماشین/محیط agent-ای** (Nimbalyst، Hermes، هر CLI که session + worktree دارد) همان سیستم را راه بیندازید.

## معماری (خلاصه)

```
                    ┌─────────────────────┐
                    │   ORCHESTRATOR      │   ← «ایجنت هد»؛ dispatch، merge، تست، حل تعارض
                    │  (docs/agent-system/│      بازیابی از PLAYBOOK-ORCHESTRATOR.md
                    │   PLAYBOOK-*.md)    │
                    └──────────┬──────────┘
        ┌──────────┬───────────┼────────────┬──────────────┐
        ▼          ▼           ▼            ▼              ▼
   agent/tape  agent/fund  agent/tech  agent/master    master (root)
   (تابلو)     (بنیادی)    (تکنیکال)   (ارشد+پرتفو)   چک‌اوت اصلی = مرج‌گاه
```

- هر ایجنت در **git worktree مستقل** با **شاخهٔ خودش** کار می‌کند؛ هیچ‌وقت مستقیم روی master نمی‌نویسد.
- هر ایجنت **قلمرو نوشتن** مشخصی دارد (feature folder خودش + تست‌های با پیشوند خودش) و بقیه چیزها فقط‌خواندنی است.
- ایجنت‌ها **هرگز به API‌ها/پوسته/محاسبات ممیزی‌شدهٔ یکدیگر دست نمی‌زنند** — این تنها چیزی است که جلوی تخریب متقابل را می‌گیرد.
- ارکستراتور تنها کسی است که **merge** می‌کند و تغییرات مشترک (AppShell، docs) را خودش می‌زند.

## فایل‌ها

| فایل | کاربرد |
|---|---|
| `PLAYBOOK-ORCHESTRATOR.md` | نحوهٔ dispatch/merge/nudge، الگوهای پرامپت، تکنیک‌های ضدقفل، رفع دام‌ها |
| `agents/tape.md` | سیستم‌پرامپت ایجنت تابلو (قلمرو + قواعد + تاریخچه) |
| `agents/fundamental.md` | سیستم‌پرامپت ایجنت بنیادی |
| `agents/technical.md` | سیستم‌پرامپت ایجنت تکنیکال |
| `agents/master-portfolio.md` | سیستم‌پرامپت ایجنت ارشد/پرتفو |
| `SETUP-NEW-MACHINE.md` | راه‌اندازی کامل از صفر روی ماشین جدید |
| `STATE.md` | اسنپ‌شات وضعیت لحظهٔ آخر (برنچ‌ها/کامیت‌ها/خط پایهٔ تست) |
| `setup-worktrees.ps1` | ساخت خودکار ۴ ورک‌تری |
